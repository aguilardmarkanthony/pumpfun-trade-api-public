# Deploy the standalone API

The default configuration uses Cloudflare Workers and Jupiter's existing on-chain router. It does not deploy a new Solana program and needs no operator wallet signature. No fee-receiving-account deposit is required; see the first-trader rent disclosure in [Fees](FEES.md).

## Settings

| Setting | Purpose |
| --- | --- |
| `SOLANA_RPC_URL` | Private HTTPS mainnet RPC URL. Never commit a provider key. |
| `TRADE_ENGINE=jupiter` | Uses the reviewed Jupiter route builder. Set in Wrangler by default. |
| `ACCESS_MODE=public` | No customer API key. Requires both Cloudflare rate-limit bindings. |
| `JUPITER_API_KEY` | Optional upstream credential for the operator's Jupiter account. Not a customer key. |
| `ACCESS_MODE=key` and `API_KEY` | Optional private self-hosted mode; clients send `Authorization: Bearer YOUR_API_KEY`. |

Public mode fails closed if edge metadata or either limiter is missing. The initial beta permits 10 requests per minute per IPv4 address or IPv6 /64, plus 30 per minute shared within a Cloudflare location. Cloudflare's limiter is approximate and local to each location, **not a global daily spending cap**. `429` includes `Retry-After: 60`. Health checks do not call RPC. Request logs are disabled.

Use a suitable RPC plan and monitor provider usage as traffic grows. The upstream Jupiter build endpoint worked without an API key during verification; this is not a promise of permanent anonymous access or unlimited capacity. Configure an operator key if your upstream account or future service policy requires it.

## Local development

Install Node 22 or 24, run `npm ci --ignore-scripts`, put the RPC URL in ignored `.dev.vars`, then run `npm run dev`. Wrangler provides local rate-limit bindings. If your local proxy does not provide edge metadata, use `ACCESS_MODE="key"` and your own random `API_KEY` in `.dev.vars`.

## Cloudflare

Authenticate Wrangler to your own Cloudflare account, choose an unused Worker name and rate-limit namespace IDs in `wrangler.jsonc`, then set the RPC secret and deploy:

```sh
npx wrangler secret put SOLANA_RPC_URL
npx wrangler deploy
```

The fixed fee recipient is deliberately not a request parameter. The default on-chain router is `JUP6LkbZbjS1jKKwapdHNy74zcZ3tLUZoi5QNyVTaV4`. The server stores infrastructure credentials only, never wallet secrets. Clients sign and broadcast with their own wallet or bot.

Before announcing an endpoint, check health, keyless access, rate limiting and unsigned simulations for both directions on each supported venue. Confirm that the returned fee recipient and fee transfer match the published policy. Source publication and successful simulations alone are not proof of a live deployment or earned revenue.

## Experimental custom router

The earlier Rust program remains under `programs/fee-router`. To research that mode, omit `TRADE_ENGINE=jupiter` and configure a reviewed deployment through `FEE_ROUTER_PROGRAM_ID`. Native recipient setup is required in that mode. Mainnet deployment would require its own funded deployment wallet; this is **not necessary for the default Jupiter service**. See [custom-router review](CUSTOM_ROUTER_REVIEW.md).
